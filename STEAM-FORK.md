# CrossAndroid with Steam

A fork of [rumpnisse/crossandroid](https://gitlab.com/rumpnisse/crossandroid) v1.7.1 (itself a fork of Namnodorel's CrossAndroid). It adds a Steam connection, so playing CrossCode on Android counts toward your Steam playtime and achievements.

## What it adds

- **Steam sign-in** (launcher: "Steam: Sign In"), three ways: scan the QR code with the Steam app on another phone; "Open in Steam app" on the same device (opens the QR challenge URL in the Steam app); or account name and password, then a Steam Guard code or an approval in the Steam app (`beginAuthSessionViaCredentials`). The password is never stored; the app keeps only the account name and refresh token in its private preferences (`steam.xml`), and backups exclude them. The token is stored encrypted with an AES-GCM key in the AndroidKeyStore (`steam/TokenVault.kt`); a plaintext token from an older build is migrated on first read, and a token that can't be decrypted counts as signed out. Account names and auth error text only reach logcat in debug builds.
- **Status panel** (same screen, once signed in): whether Steam confirmed "Playing CrossCode", how many achievements Steam has, how many the game reported, verified and pending, and a "Check now" button that re-sends anything missing and re-reads the stats.
- **Playtime**: while the game activity is in front, the app tells Steam you are playing app 368340. That shows "Playing CrossCode" to friends and adds to your hours. It clears on pause. A minute after the game leaves the front (and the Steam screen is closed), queued unlocks are synced and the connection is closed; it reconnects when the game is back. Reconnects back off from 5 s to 2 min, reset only by a successful logon. The app confirms it from Steam's playing-session and own-persona answers.
- **Achievements**: `SteamFeature` waits for `sc.trophies` and sets `ig.greenworks.greenworks` to a JS stub that calls `CrossAndroidSteam.unlock(id, live, name)`. A `replaying` flag around `onStorageGlobalLoad` tells new unlocks from the boot replay of the save. `SteamBridge` queues each unlock, reads the user's stats and schema (ClientGetUserStats), sets the achievement's bit, stores it (ClientStoreUserStats2), then reads the stats back and logs "Unlocked on Steam: [...] (verified...)". Replays of what Steam already has log "Already on Steam: X" and are skipped. Only ids that both the Steam schema and the game's own trophy list contain are accepted (`steam/SteamRules.kt`); anything else logs "Refusing unknown achievement id" and is dropped. Failed uploads retry with a doubling wait (30 s up to 10 min, 8 tries), then stop until "Check now". If Steam refuses both the stats and an ownership ticket, the account doesn't own CrossCode: nothing is uploaded, "playing" isn't sent, and the panel says so.
- **Achievement pop-ups**: a Steam-style card in the bottom-right corner (the achievement's own art from Steam's CDN, "Achievement Unlocked!", name, description) that rises out of the screen edge, glints and sinks back. Only for live unlocks; earlier unlocks synced at boot get one summary card. Setting: Settings > Steam > "Achievement pop-ups" (`steam_achievement_popups`, on by default).
- **Built-in extension-asset-preloader**: with CCLoader2, mods that require `extension-asset-preloader` (Azure's Adjustments, xenons-playable-classes) failed with "mod ... is missing". When no installed mod provides it, the app serves a stand-in from memory (`features/BuiltInMods.kt`) whose postload fills `ig.fileForwarding` from the app's extension scan.
- **Mod patch fixes** (`PatchStepsApplier.kt`, `PatchCondition.kt`): the native patcher now matches CCLoader where mods relied on it. INCLUDE and IMPORT take object or array files (an object is deep-merged), base files may have an array root, `game:` paths see mod-provided assets, and cc-alybox IF steps (`cond`) that check for other mods (`activeMods.find(e => e.name === '...')`) are evaluated against the installed mods; other conditions still run their steps. Without these, xenons-playable-classes crashed on its character select map and added Arcane Lab content without Arcane Lab. `InstalledModPatchesTest` runs a real mods folder through the patcher: `MODTEST_TREE=<copy of assets/> ./gradlew testDebugUnitTest`.
- **Raw stick values** (`PhysicalControllerBridge.kt`): physical sticks reach the game as Android reports them, like a desktop browser's Gamepad API. The old per-axis 0.1 dead zone zeroed slight off-axis pushes, so aim snapped flat; the game applies its own dead zones (0.24 left, 0.265 right). Stick shaping for handhelds is a separate CrossCode mod, [Smooth Stick Aim](https://github.com/catmona/crosscode-mods/tree/main/smooth-stick-aim), not part of this app.
- **Launcher tile**: the manifest declares `android:isGame="true"` and `android:appCategory="game"`.
- **Debug builds only**: `adb shell am broadcast -a de.radicalfishgames.crosscode.PREVIEW_POPUP [--es id <api name>]` previews the pop-up for an achievement Steam already has (nothing is sent to Steam); `... -a de.radicalfishgames.crosscode.FPS_PROBE` logs 10 s of in-page frame pacing to logcat (tag CCLoader).
- **Full save import**: put a desktop `cc.save` at `Android/data/de.radicalfishgames.crosscode.steam/files/import/cc.save`. On the next launch it replaces localStorage `cc.save`, which holds every slot and global data. The old save is kept next to it as `cc.save.before-import-<time>`. The imported save's achievements are held back until the user answers "Sync N achievements from the imported save to Steam?"; a "Don't sync" is remembered, so those ids are never sent from a replay (live unlocks still are).

Code: `app/src/main/java/de/radicalfishgames/crosscode/steam/` and `features/SteamFeature.kt`, `features/BuiltInMods.kt`, `features/FullSaveImportFeature.kt`. Tests: `./gradlew testDebugUnitTest` (schema parsing, built-in mod serving, token sealing, the achievement allow-list and retry rules, mod patching).

## Before making this repo public

The owner plans to publish this once it works well. Before that:

- [x] **License**: neither upstream repo (rumpnisse or Namnodorel) declares a license. The maintainer chose to publish as a fork, like the other public CrossAndroid forks, with upstream's history and credits kept and a take-down offer in the README.
- [x] **No GPL code**: GameNative is GPL-3. The Steam code here is written from the protocol, not copied from GameNative. Keep it that way, or adopt GPL-3 for the whole project. JavaSteam is MIT and ZXing is Apache-2.0; both are fine to bundle and are listed on the About screen.
- [x] **No secrets**: never commit `keystore.properties`, keystores, `local.properties`, refresh tokens or logs with tokens. Check the history (`git log -p`) before publishing.
- [x] **Identity**: commits use the GitHub noreply address (`30540400+catmona@users.noreply.github.com`), set as repo-local git config.
- [x] **Steam terms**: this signs in with the user's own account and only reports their own play. Say clearly in the README that it is unofficial and not affiliated with Valve or Radical Fish Games, and that you need to own the game on Steam.
- [x] **Package name**: the app id is `de.radicalfishgames.crosscode.steam` (label "CrossCode (Steam)"), so it installs beside upstream. The Kotlin namespace stays `de.radicalfishgames.crosscode`, so the launch component is `de.radicalfishgames.crosscode.steam/de.radicalfishgames.crosscode.LaunchActivity`.
- [x] **minSdk** (now 26): upstream says 24, but JavaSteam uses `java.util.Base64` (API 26). Raise minSdk to 26, or enable core library desugaring.
